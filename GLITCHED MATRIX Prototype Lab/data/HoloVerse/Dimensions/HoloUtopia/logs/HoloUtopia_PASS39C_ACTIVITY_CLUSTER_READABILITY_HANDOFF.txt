HoloUtopia Pass 39C - Simulation Hub Activity Cluster Readability

Scope:
- Continue the district-activity pass sequence.
- Keep Residential as the home/garrison source.
- Keep Simulation as the central hub according to lore.
- Make Simulation Hub activity visually readable with pods, terminals, plinths, and standing slots.
- Preserve street-safe pathfinding: visible citizens must not stand on building roofs/footprints.

What changed:
1) Added data/database/utopia/simulation/simulation_hub_activity_clusters.json
   - Defines named Simulation Hub activity clusters.
   - Each cluster targets an authored schedule node.
   - Each cluster provides standing slot offsets for citizens.

2) Added data/HoloUtopia/holoutopia_simulation_hub_visuals.py
   - Attaches collisionless activity props under the integrated city root.
   - Draws simple line-model pods, consoles, plinths, briefing steps, and lore terminals.
   - No citizen contact circles or labels.

3) Improved pathfinding
   - District activity representatives prefer named activity-cluster standing slots.
   - If a cluster slot is unavailable, fallback remains street/activity-pad safe.
   - Building-footprint exclusion remains active.

4) Improved activity frames
   - Simulation Hub representatives now carry activity_cluster_id and activity_stage.
   - Citizen tasks remain virtual/capped.

5) Updated runtime config
   - Schema 7.
   - New render layer: activity_cluster_props.
